# 系统接口设计规范

**文档编号**：TECH-API-2025-003
**版本**：V1.2
**适用范围**：研发中心全体开发人员
**密级**：内部公开

## 一、总则

为统一公司各业务系统的接口设计风格，降低系统间联调成本，提升接口的可维护性与安全性，特制定本规范。本规范适用于公司内部所有新开发及重构的 HTTP 接口，第三方对接接口参照执行。

## 二、接口风格与命名

1. 公司对外及系统间接口统一采用 RESTful 风格，资源名使用复数名词，避免使用动词；
2. 接口路径统一以 `/api/v1/` 开头，其中 v1 为主版本号，重大不兼容变更时递增；
3. 查询类接口使用 GET，新增使用 POST，修改使用 PUT，删除使用 DELETE，禁止用 GET 执行写操作；
4. 资源路径一律使用小写字母加中划线分隔，例如 `/api/v1/leave-requests`。

## 三、请求与响应规范

1. 除文件上传外，请求体与响应体统一使用 JSON 格式，字符编码为 UTF-8；
2. 统一响应结构包含 code、message、data 三个字段，业务处理成功时 code 为 0；
3. 时间字段统一使用 ISO 8601 格式（如 2025-06-01T09:00:00+08:00），时区为东八区；
4. 分页接口统一使用 page（页码，从 1 开始）与 page_size（每页条数，默认 20，最大 100）两个参数；
5. 接口返回列表时必须同时返回 total 总条数字段，便于前端分页展示。

## 四、性能与稳定性要求

1. 普通业务接口响应时间不得超过 500 毫秒，复杂报表类接口不得超过 3 秒；
2. 系统间同步调用的默认超时时间为 30 秒，超时后调用方应立即失败并记录日志；
3. 对外开放的查询接口默认限流为每个调用方每分钟 1000 次，超出后返回 429 状态码；
4. 核心接口必须支持幂等，写操作接口应在请求头中携带 X-Request-Id 用于幂等去重。

## 五、错误码规范

1. HTTP 状态码与业务错误码配合使用：参数校验失败返回 400，未认证返回 401，无权限返回 403，资源不存在返回 404，服务器内部错误返回 500；
2. 业务错误码采用六位数字，前两位代表业务域（如 10-用户域、20-知识库域、30-文档域），后四位为域内错误编号；
3. 所有错误响应必须在 message 中返回面向开发者的中文描述，禁止返回空消息或堆栈信息；
4. 各业务域错误码由架构组统一登记分配，开发团队不得私自占用他域错误码。

## 六、安全规范

1. 所有非公开接口必须通过网关鉴权，携带有效的 JWT Token，禁止在 URL 中传递 Token；
2. 涉及敏感数据（薪酬、个人信息）的接口必须在日志中脱敏，日志保存期限不少于 180 天；
3. 接口入参必须在服务端完成校验，不得依赖前端校验，防止越权与注入攻击；
4. 内网接口间调用如涉及资金或审批操作，必须启用签名校验与防重放机制。

## 七、文档与变更管理

1. 所有接口必须在统一接口平台上登记，并提供 OpenAPI 3.0 格式的描述文件；
2. 接口变更遵循"先通知、后上线"原则，不兼容变更须提前 5 个工作日通知所有调用方；
3. 已废弃接口须保留 3 个月的过渡期，并在响应头中标记 Sunset 日期；
4. 本规范由架构组负责解释，自发布之日起施行。
